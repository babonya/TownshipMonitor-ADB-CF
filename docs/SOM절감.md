# SOM(AI 상품 매칭) 사용량 줄이기 — 분석과 설계 (2026-10-16)

## 배경
- 중계기(addons/cf-som-proxy.mjs)가 봇의 `product_match`(필요 상품 이미지 a vs 시장 칸 이미지 b)를 Cloudflare Workers AI로 넘긴다.
- 무료 한도 하루 10,000 뉴런(UTC 0시 = 한국 09:00 초기화). 10-15에는 약 12~15시간 운영 후 소진 → 이후 SOM_HTTP_502로 반복 정지(정지사례 #8).
- 고유 쌍만 setup-local/som-pairs/<id>/{a.png,b.png,result.json}에 저장 중(완전히 같은 바이트 쌍의 재호출은 저장 안 됨 → 실제 호출은 더 많음).

## 자료 분석(저장 쌍 8,477개)
- 답: different 7,837(92%), same 585(7%), uncertain 55.
- 비슷한 이미지끼리 묶으면(가운데 2/3 영역 16×16 축소, 평균 화소 차 6 이내): 필요 상품 그룹 458, 시장 칸 그룹 364, (필요,칸) 조합 4,080 → **호출의 약 52%가 이미 물어본 조합의 재질문**.
- 상품 하나의 시장 모습은 평균 1.4가지(같은 상품이 칸에서 거의 같은 모습).
- **시간순 시뮬레이션**(각 쌍을 그 이전 자료만으로 답할 수 있었나):
  | 기준 | AI 없이 답한 비율 | AI와 일치 | 잘못 same(오구매 위험) | 잘못 different |
  |---|---|---|---|---|
  | 차 4 | 47.5% | 99.28% | 1 | 28 |
  | 차 6 | 53.9% | 99.26% | 1 | 33 |
  - 불일치의 대부분은 AI가 같은 조합에 답을 바꾼 경우(AI 자체 흔들림, 그룹 내 충돌 37건).

## 설계(단계별, 안전 우선)
1. **완전 동일 쌍 캐시**: a·b 바이트 해시가 같으면 저장된 답 재사용. 위험 0. 저장 안 되던 재호출까지 절감.
2. **근접 쌍 캐시**(위 시뮬레이션): 이전 쌍 중 a·b 모두 가까운 것들의 답이 하나로 일치하면 재사용. 답이 갈리거나 uncertain이 섞이면 AI.
   - same은 더 엄격하게: AI same을 2번 이상 받은 조합이거나 clef 재확인까지 통과한 것만 캐시 same. 오구매 방지(AGENTS.md: 불확실하면 추측 등록 금지).
3. **상품 정체 DB**(다음 단계): same 답으로 '필요 상품 그룹 ↔ 시장 칸 모습'을 상품 ID로 묶는다. 칸 모습이 상품 P로 확정되고 필요 상품이 Q로 확정되면 P==Q로 즉시 판정(새 조합이어도). 새 모습만 AI.
   - 기존 원칙과 연결: 상품 기준 이미지는 실제 게임 캡처에서 얻고(som-pairs가 실캡처), 원본·해시·영역 보관.
4. **검증 방식**: 적용 전 '그림자 모드' — 로컬 답을 계산·기록하되 AI도 호출해 일치율 측정. 일치율·오same 0을 확인한 기준만 실제 적용. 적용 후에도 표본(예: 5%)은 AI로 계속 대조.
5. 측정: 중계기 카운터(호출/캐시 응답/AI 호출/불일치)를 runtime 로그로 남겨 하루 단위 절감량 확인.

## 기대 효과
- 1+2단계만으로 AI 호출 약 50~60% 감소 추정 → 하루 한도 안에서 거의 24시간 운영 가능 범위.
- 3단계까지 가면 자료가 쌓일수록 새 상품·새 모습만 AI(장기적으로 대부분 로컬).

## 구현 상태 (2026-10-16 08:xx, 운영자 결정 "1·2단계, same은 엄격")
- `addons/som-cache.mjs` + `addons/cf-som-proxy.mjs` 연결. 순서: 사전 거르기 → 캐시(동일 → 근접) → AI(2.4초+재시도) → 답을 저장·캐시에 추가.
- 근접 규칙: 거리 6 미만 이웃이 모두 different면 different. same은 거리 4 미만 same 기록 2개 이상 + 다른 답 0일 때만. uncertain·멀찍한 same이 섞이면 AI.
- 시작 시 som-pairs 8,477쌍 읽기 12초(그동안은 동일 쌍만 캐시). 근접 답의 5%는 AI로 그림자 대조, 불일치는 runtime/cf-som-proxy.log에 `cache mismatch`.
- 통계: runtime/cf-som-cache.log에 product_match 100건마다 (요청, AI 호출, 사전거르기, exact/near/nearSame/miss/shadow).
- 검증: 구현 규칙으로 8,477쌍 시간순 재생 → 51.6% 로컬 응답, AI와 99.91% 일치, 오same 0, 놓친 same 0. 8099 포트 시험 중계기로 동일 쌍 40건 HTTP 응답 확인(AI 호출 0).
- 남은 일: 실운영 하루 통계로 실제 절감률 확인 → 3단계(상품 정체 DB) 여부 결정.

## 진행 방향 (운영자 결정 2026-10-16)
1. 캐시(1·2단계)로 하루 더 운영 → runtime/cf-som-cache.log로 실제 절감률·남은 AI 호출 성격·그림자 불일치 확인.
2. 그 결과로 3단계 상품 정체 DB 설계·구현(처음엔 그림자 모드).
3. 이후 운영: AI 답을 검증해(same은 2회 이상+재확인 통과, 그림자 표본 대조, 충돌 감지) DB에 **자동으로** 쌓되 중복은 최소화(같은 모습은 대표 서명만 유지, 그룹당 상한) → 이미 매칭한 것은 AI를 다시 쓰지 않게.
