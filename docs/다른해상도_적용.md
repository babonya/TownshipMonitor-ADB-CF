# 다른 해상도·다른 폰에 적용하기

이 봇은 개발자 폰(가로 1600x720)에서 실측한 값으로 만들어졌다. 1544x720 프로필도 있지만 실기기 정확도는 검증하지 않았다.
다른 해상도에서 쓰려면 아래 표의 "해상도에 묶인 것"만 자기 화면으로 다시 등록하면 된다. 나머지는 비율·상대값이라 그대로 동작한다.
AI(바이브코딩)에게 맡길 때는 이 문서와 `docs/정지사례.md`를 먼저 읽게 하면 된다.

## 원칙
- 좌표·영역은 모두 **화면 비율(0~1)** 로 저장한다(AGENTS.md "퍼센티지 좌표 규약"). 픽셀은 실행할 때 계산한다.
- **그림(템플릿)은 그 해상도의 실제 게임 캡처에서 잘라야 한다.** 다른 해상도 그림을 늘려 쓰지 않는다.
- 캡처 폭으로 프로필을 고른다: `tools/android-adb-observation.mjs` → `reference/som/android-<폭>/`.
- 새로 등록한 것은 저장 화면 수십~수백 장으로 "예전과 판정이 같은지 / 엉뚱한 화면에서 안 잡히는지"를 확인한 뒤 적용한다.

## 무엇이 해상도에 묶여 있나

| 기능 | 파일 | 해상도에 묶인 것 | 다른 해상도에서 할 일 |
|---|---|---|---|
| 화면 프로필(헬기·시장·마을 판별, 칸 위치) | `reference/som/android-<폭>/profile.json` + 템플릿 | 템플릿 그림, `market.rows`(두 줄 높이), `markers[].offset` | 그 폭 폴더를 만들고 자기 캡처로 템플릿·비율을 등록. 시장 칸 찾기 띠(`vision.py` marks)는 rows·offset에서 자동 계산 |
| 팝업 규칙(레벨업, 선물, 이벤트 X 등) | `reference/som/android-<폭>/<규칙>/profile.json` + 잘라낸 그림 | 제목·버튼 그림, 찾는 크기 범위(±1.5%) | 자기 화면에서 같은 팝업을 캡처해 제목+버튼을 잘라 새 규칙 폴더로 등록(기존 규칙 profile.json을 본떠 sha256·영역 갱신) |
| 시장 SOLD 2x2 끝 판정 | `tools/som/actions.mjs` soldBlockView | 칸 간격 비율(가로 = 칸 너비×1.27, 세로 = 칸 높이×1.94, 1600에서 실측) | 칸 배치 비율이 같으면 그대로. 다르면 자기 시장 화면에서 칸 간격÷칸 크기를 재서 고친다 |
| 시장·헬기 빠른 인식(팝업 검사 생략) | `tools/som/android_vision.py` _lit | 없음(밝기 차이 10 기준) | 그대로 |
| 마을 카메라 복원 | `addons/town-camera/` | 기준 건물 그림(창고·시장·헬기장·비행장)과 기준 위치 | `마을등록.cmd`(register_town.py)로 자기 마을에서 등록. 드래그·줌은 비율, 화면 비교는 축소 이미지라 그대로 |
| 마을에서 시장·창고 누르는 자리 | profile.json `town.marketTap`/`barnTap` | 등록한 사람 마을 배치 | 자기 마을 기준 카메라에서 다시 잰다(카메라 복원과 짝) |
| 기기 확인 캐시(3초), 대기 시간 | `tools/android-adb-device.mjs`, `tools/som/action-policy.mjs` 등 | 없음 | 그대로(느린 폰이면 대기를 늘려야 할 수 있음) |
| 시장 스와이프 | `tools/android-market-drag.mjs`, `tools/som/market-scroll.mjs` | 거리는 프로필 비율, 시간 400ms | 그대로 |

## 등록·검증 순서(팝업 하나 예)
1. 봇이 멈춘 화면을 `adb exec-out screencap -p`로 PNG 저장(폰 해상도 그대로).
2. 제목 글자와 누를 버튼(또는 기준이 될 글자)을 잘라 `reference/som/android-<폭>/<이름>/`에 저장하고, 기존 규칙의 profile.json을 복사해 영역·sha256을 고친다.
3. `tools/som/android_vision.py`의 팝업 규칙 목록에 이름을 추가한다.
4. 저장 화면 전체에 돌려 그 화면에서만 잡히는지 확인 → 모니터 '일시중지' → '프로그램 재시작' → '시작'으로 적용.
5. `docs/정지사례.md`에 원인·파훼법·확인 결과를 적는다.

## 코드 주석 규칙
- 바꾼 곳에는 `[날짜 이유]` 주석을 단다(예: `[2026-10-20 속도]`, `[사용자 결정]`). 왜 그렇게 했는지, 무엇을 측정했는지를 한 줄로.
- **해상도에 묶인 값**(픽셀, 실측 비율, 점수 기준)은 "어느 해상도에서 실측했는지"와 "다른 해상도에서 확인하는 방법"을 주석에 같이 적는다.
