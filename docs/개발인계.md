# 개발 인계 — Township 자동 거래봇 (원작자 프로그램 + 애드온)

새 AI 세션은 이 문서를 먼저 읽고, 필요한 부분만 grep으로 더 찾아 읽는다. 게임 동작 규칙은 `AGENTS.md`(원작자), 운영 규칙은 `CLAUDE.md`.

## 1. 구조
원작자 프로그램:
- `artifacts/TownshipMonitor/TownshipMonitor.exe` — C# .NET 8 GUI 모니터(소스 `apps/TownshipMonitor`). 시작/일시중지/프로그램 재시작 버튼.
- `tools/mumu-monitor-cli.mjs --bridge` — 실제 두뇌(Node). `tools/*.mjs`. stdout이 모니터와의 JSON 프로토콜이므로 `console.log` 금지.
- `tools/som/*`, `tools/township-perception` — 화면 인식(OpenCV 템플릿, RapidOCR, Python venv `.venv-perception`)과 SOM 클라이언트. SOM(System One) = 결정 모델 API로, 시장에서 "주문 상품 vs 시장 칸 상품이 같은가"를 묻는 데 쓴다.
- `reference/som/android-1600`(1544 폴더도 있음) — 화면 프로필·템플릿·팝업 규칙 등록 원본.
- `Start-ADB.cmd` — 원작자 진입점. 기본은 정지 상태(stop=true), 모니터에서 시작을 눌러야 동작.

애드온(`addons/`, 이 배포본에서 추가):
| 파일 | 역할 |
|---|---|
| `cf-som-proxy.mjs` | 127.0.0.1:8087 중계기. 봇의 SOM 요청을 Cloudflare Workers AI(Clef)로 넘긴다. 캐시·사전 거르기 연결, 오류를 `runtime/cf-som-proxy.log`에 기록 |
| `som-cache.mjs` | 답 캐시. 동일 쌍 → 근접 쌍(same은 엄격) → AI. 씨앗 `addons/som-seed/som-seed.bin.gz` 로드 |
| `som-prefilter.mjs` | 색 히스토그램으로 명백히 다른 쌍은 AI 생략(기본 off, `CF_SOM_PREFILTER`) |
| `addons/som-seed/` | 배포본에만 있는 근접 쌍 캐시 씨앗(압축 서명, 이미지 없음). `tools/release/Export-SomSeed.mjs`가 생성 |
| `watchdog.ps1` | 감시. 6분 무입력·오류 일시정지·헛돌기를 감지해 프로그램 재시작·시작, 폰 잔여 raw 삭제 |
| `watchdog-alert.ps1` | 감시의 알림 판정·중복 억제·텔레그램 전송(환경변수 없으면 알림만 생략) |
| `loop-check.mjs` | 최근 완료 동작 10개가 모두 같은 종류·replanned면 LOOP(헛돌기) 판정 |
| `delivery-count.mjs` | `state.json`의 오늘 납품 수 출력(시간당 납품 0 알림용) |
| `town-camera/`, `pinch/` | 마을 카메라 자동 복원. `pinch/Pinch.java`(+`build/classes.dex`)는 app_process로 두 손가락 핀치를 주입(adb `input`엔 멀티터치가 없음). `town_camera.py`가 창고 기준 이미지로 배율·위치를 맞춘다 |
| `setup/Setup-Township.ps1`, `setup/probe-device.mjs` | 처음설정/점검/빠른확인(런타임·venv·Cloudflare·텔레그램·폰 해상도·게임 설치·`setup-local/device.json`). 기기 바인딩 CLI가 없어 `probe-device.mjs`가 대체 |
| `Start-TownshipCF.cmd`, `Start-Watchdog.cmd`, `Start-Proxy.cmd` | 중계기·감시 기동 래퍼 |
| `tools/release/Make-Release.ps1` | 배포 zip 생성 + 비밀 검사 |

루트: `처음설정.cmd`(대화형 설정), `점검.cmd`(점검만), `시작.cmd`(빠른 확인 후 `Start-TownshipCF.cmd`), `README_설치.txt`.

## 2. 실행 흐름
`시작.cmd` → `Setup-Township.ps1 -Quick`(준비 확인) → `addons\Start-TownshipCF.cmd`:
1. `ANDROID_ADB_SERVER_PORT=15037` 지정, `CLOUDFLARE_ACCOUNT_ID` 확인.
2. 중계기(`addons\cf-som-proxy.mjs`, 8087)가 없으면 최소화 창으로 기동하고 `/health` 대기.
3. 감시(`Start-Watchdog.cmd` → `watchdog.ps1`) 기동(이미 있으면 즉시 종료).
4. `Start-ADB.cmd` → 모니터 창. 모니터에서 '시작'을 누르면 봇이 동작.
- 반드시 탐색기에서 실행한다. AI 세션의 자식 프로세스로 띄우면 세션 종료 시 감시·중계기가 같이 죽는다.
- 사용자 환경변수 `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_AUTH_TOKEN`(필수), `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`(선택)를 `.cmd`가 레지스트리에서 직접 읽어 넣는다. 파일에는 두지 않는다.
- 산출물(`runtime/`): `watchdog.log`, `alerts.log`, `hourly.log`, `cf-som-proxy.log`, `cf-som-cache.log`, `town-camera.log`, `stall-shots/`(정지 시 캡처). `setup-local/unknown-screens/`는 모르는 화면 캡처(팝업 규칙 등록 후보), `setup-local/som-pairs/`는 AI가 답한 쌍 기록.

## 3. 원본 대비 변경 목록
원작자 파일을 고친 곳(새 원작자 버전을 받으면 다시 적용해야 함). 동작 원인·검증 수치는 `docs/정지사례.md`, `docs/SOM절감.md`.

**원본 수정**
- `tools/android-adb-observation.mjs`: 캡처 폭 1544|1600 허용, 폭에 따라 `reference/som/android-<폭>` 프로필 선택. `deployment/init-session.mjs` 오류 문구. `tools/android-adb-restart.mjs`: adb 프로세스 검사 WMI 필터에 `ThreadCount > 0` 추가(좀비 adb 제외).
- `tools/som/android_vision.py`: Town Cards 감지, 팝업 규칙 목록(level-up, quit-finished, piggy-bank, treasure-hunt, card-received 등), 마을 카메라 확인(`town_camera_ok`, 불일치면 `cameraMismatch`), 탭 보정(`shift_town_target`: 창고 위치 기준으로 시장·창고 탭 이동), 미니게임 감지 시 핀·닫기 채움. 1544 프로필 폴더에 규칙이 없으면 android-1600 것으로 대체.
- `tools/som/town_cards.py`(신규), `tools/som/popup_rules.py`(신규, PopupRuleDetector; `arrow_guide`는 화살표 4방향 → 밝은 부분, 못 찾으면 화살표 끝 앞 20px).
- `tools/som/vision.py`: 헬기 초록 핀 보조 검출 1차(핀 아래 끝이 어두운 경우)·2차(가려진 핀을 원 맞춤으로).
- `tools/som/delivery.mjs`: `skipMinigame`(미니게임 화면을 새로고침 대기 주문처럼 취급해 다른 주문 선택), 납품 집계(SEND 2탭 완료+정상 복귀면 replanned도 1건), 마을 카메라 복원 도구 호출(연속 3회 실패 시 hold `TOWN_CAMERA_UNRESTORED`).
- `tools/som/actions.mjs`: `som_send` 결과 판정 — 핀을 읽은 화면에서 보낸 주문의 초록 핀이 사라지면 orderHash 없이도 confirmed.
- `tools/som/market-visit.mjs`: 4개 구매 후에도 남은 필요 상품이 있으면 사지 않고 시장 끝까지 스크롤하며 매칭만(없는 상품 집계가 쌓이게).
- `tools/som/market-session.mjs`: `MARKET_SEARCH_FAILURE_LIMIT`은 원작자 값(2) 유지.
- `tools/android-adb-device.mjs`, `tools/android-raw-capture.mjs`(신규), `tools/adb.mjs`, `tools/android-market-drag.mjs`, `tools/mumu-capture.mjs`: 폰 PNG 인코딩 제거 → `exec-out screencap` raw를 PC에서 PNG 변환, 끝점 캡처도 raw. `launchGameIfHome`(게임 꺼짐+전면이 런처면 게임 실행, 60초에 1회).
- `tools/mumu-retention.mjs`, `tools/mumu-store.mjs`: 상태 정리 때 해당 프레임 PNG도 삭제(고아 파일 누적 방지).
- `reference/som/android-1600/profile.json`: `town.marketTap`=(0.35, 0.5833) 시장 한가운데, `barnTap`=(0.48625, 0.35) 창고 몸통, `town.anchor` 탐색 영역 사방 8px 확대. 생성기 `addons/make_android_1600.py`의 검증 탭 값도 같음. 이유: 가장자리를 누르면 카메라 오차 안의 작은 어긋남에도 빈 땅을 눌러 헛돎(정지사례 #9, #15, #14).
- `reference/som/android-1600/{level-up,quit-finished,piggy-bank,treasure-hunt,card-received,town-cards,arrow-guide,event-close,continue-button}/`: 팝업 규칙·템플릿(전부 제목과 버튼이 함께 보일 때만 동작).

**애드온으로 추가**: 위 구조 표의 `addons/*` 전부, `docs/정지사례.md`, `docs/SOM절감.md`.

## 4. 점검 방법
- 먼저 `runtime/alerts.log`, `runtime/hourly.log`를 `tail`로 본다.
- 상태: `runtime/mumu-autonomous-transport/.monitor/delivery.json`의 phase·reason, 같은 폴더 `state.json`의 actions(최근 시각·종류)·dailyDeliveries.
- 감시: `runtime/watchdog.log`(정지 감지·재시작). 헛돌기: `node addons/loop-check.mjs`(OK/LOOP + 무입력 분). 카메라: `runtime/town-camera.log`.
- AI 중계기: `runtime/cf-som-proxy.log`(HTTP 429 = 무료 한도 소진, `cache mismatch` = 캐시 불일치), `runtime/cf-som-cache.log`(100건마다 누적 통계: 요청·AI 호출·exact/near/miss 등).
- 폰(adb 경로·포트는 CLAUDE.md): `shell dumpsys window | grep mCurrentFocus`, `exec-out screencap -p`. 잔여 `/data/local/tmp/township_endpoint_*.raw`는 캡처 후 멈춘 흔적.
- 복구: 폰 잔여 raw 삭제 → 모니터 일시중지 → 프로그램 재시작 → 새 창에서 시작. 모니터가 꺼져 있으면 사용자가 끈 것이므로 다시 켜지 않는다. 모니터 조작은 UIAutomation(버튼 이름 '시작'/'일시중지'/'프로그램 재시작').
- 처음 설정 확인: `점검.cmd`(= `Setup-Township.ps1 -CheckOnly`).

## 5. 알려진 한계·다음 할 일
- **마을 카메라 복원은 배포본에서 꺼져 있다**(2026-10-17): `addons/town-camera/barn-1600.*`·`source-town-1600.png`는 만든 사람 마을의 창고 모습·위치라 남의 마을에선 항상 "어긋남" → 복원 3회 실패 → `TOWN_CAMERA_UNRESTORED`로 멈춘다. 그래서 Make-Release가 이 파일을 빼고, `android_vision.py`는 파일이 없으면 기능을 끈다. 할 일: 사용자가 카메라를 맞춘 상태에서 자기 창고를 캡처해 기준 이미지(해상도별 `barn-<폭>.json/png`)를 등록하는 도구.
- **마을 탭 좌표도 마을 배치에 묶여 있다**: 프로필의 `town.marketTap`/`barnTap`은 등록한 사람 마을의 시장·창고 위치(원작자 readme "카메라·배치가 등록 원본과 같아야 함"). 마을 배치가 다르면 시장·창고 탭이 빗나간다 — 자기 마을로 다시 등록하는 절차가 필요.
- **DAILY REWARDS(출석 보상)** 미등록: 빛나는 칸이 오늘 보상인데, 수령 전 화면 캡처가 없어 보류. 새 날 첫 실행에서 캡처 확보 후 규칙 등록.
- **새 이벤트 안내 창**은 매번 다르다(보통 X, X 없으면 START). 감시가 '화면 인식 불가'로 재시작할 때 `setup-local/unknown-screens/auto-*.png`에 저장하니 그 캡처로 규칙을 등록한다.
- **1544 프로필은 실기기 정확도 미검증**이다(기동 시험만 통과). 카메라 복원은 크기가 다르면 건너뜀. 1600 기준으로 검증되어 있다.
- 기기 **바인딩 CLI가 없다**(원작자 배포판에도 없음) → `addons/setup/probe-device.mjs`로 대체. 재바인딩은 안내만 가능.
- 처음설정 전체 흐름(대화형 입력·winget·venv·probe/init)은 새 PC에서 끝까지 시험되지 않았다.
- card-received·화살표 4방향 규칙은 실기기에서 충분히 확인되지 않았다.
- AI 절감 3단계(상품 정체 DB)는 캐시 통계를 본 뒤 설계(`docs/SOM절감.md` '진행 방향').
- Cloudflare 무료 한도는 하루 10,000 뉴런(UTC 0시 = 한국 09시 초기화). 캐시 적용 후 429는 없었고 적중률 60~75%.
- 원격 켜기/끄기용 Tailscale 웹 페이지는 예정(미구현).
- 원작자가 시장 새로고침 버프를 적용하면 하루 약 350건이 가능하다고 한다. 우리 쪽은 정지 시간 때문에 그보다 적었다.
- 안정되면 원작자에게 변경점·효과·이유를 정리해 알린다(`docs/원작자_변경보고.md` 초안은 개인 문서라 배포본에 없음).
- 로컬 AI(원작 d1-3B)는 NVIDIA GPU 12GB급 기준이라 작은 GPU에서는 Cloudflare 중계기를 쓴다.
