## 운영 점검(운영자 결정 2026-10-16)
1. **첫 시작 관찰**: 매크로를 켤 때 Claude가 게임을 직접 켜고(adb monkey) 첫 화면부터 봇이 첫 배송까지 가는지 지켜본다. 멈춘 화면은 캡처를 `setup-local/unknown-screens/`에 남기고 위 표에 기록.
2. **1시간 점검**: 정지 여부(최근 동작 5분 이내, 사유, 감시 로그 runtime/watchdog.log, 카메라 로그 runtime/town-camera.log). 멈췄으면 원인 분석 → 이 문서에 기록 → 복구.
3. 모르는 팝업은 결제·구매 버튼을 절대 누르지 않고 닫기(X)만.

## 상세
- **#1 시간초과**: 폰 /data/local/tmp/township_endpoint_*.raw가 완전한 크기(4608016)로 남음 = 캡처는 끝났고 그 뒤 단계에서 멈춤. 근거 코드 tools/android-adb-device.mjs:154, tools/mumu-restart-current-screen.mjs. 근본 개선안(미구현): som_scroll 시간초과만 손가락 UP 후 재관측으로 계속.
- **#2 카메라**: 핀치는 adb `input`에 멀티터치가 없고 /dev/input 쓰기는 SELinux 거부 → app_process로 MotionEvent 주입(addons/pinch). 손가락 간격 r배 → 줌 r^0.45배. 가장자리에서 확대하면 창고가 밖으로 밀려나 먼저 가운데로 옮김.
- **#8 진짜 원인(10-16 06:25 확인, runtime/cf-som-proxy.log)**: Cloudflare 응답 `HTTP 429 code 4006 "you have used up your daily free allocation of 10,000 neurons"` = **Workers AI 무료 일일 한도 소진**. 한도는 UTC 0시(한국 09:00)에 초기화 → 그 전엔 재시작해도 첫 AI 판정에서 다시 정지. 대책: ① **적용(10-16 08시대)** 동일·근접 쌍 답 캐시로 AI 호출 약 50% 절감 예상(docs/SOM절감.md) ② Workers Paid 전환(운영자 결정) ③ 한도 소진 시 감시 재시작 중단·09:00 재개. 중계기는 06:21부터 첫 시도 2.4초+재시도 1회로 변경(일시적 지연용, 한도 소진엔 무효).
- **#8 중계기 502**: 01:19 점검에서 발견(마지막 동작 00:00:51, 그 전 시장 열기가 replanned 9회). Cloudflare 쪽 실패 이유는 당시 로그가 창에만 있어 확인 불가 → 파일 기록 추가. 자정 직후라 일일 한도·점검 가능성도 의심(Cloudflare 무료 한도는 UTC 0시=한국 9시 초기화라 직접 원인은 아닐 것). 사람이 일부러 멈출 때는 모니터를 닫는 것을 권장(이 사유가 남은 일시정지는 감시가 재시작함).
- **#9 시장 열기 반복**: 같은 입력이 결과 없이 반복되는 '헛돌기'는 무입력 감시로 안 잡힌다. 탭 좌표는 가장자리 말고 대상 한가운데를 고른다(원칙). 10-16 04:48 추가 파훼: ① android_vision.py가 카메라 확인 때 찾은 창고 위치·배율로 시장·창고 탭을 보정(shift_town_target) — 허용 오차 안 어긋남도 탭이 따라감. ② addons/loop-check.mjs(최근 완료 동작 10개가 모두 같은 종류·replanned면 LOOP) → 감시가 재시작(최소 10분 간격). 남은 후보: 시간당 납품 0 경고.
