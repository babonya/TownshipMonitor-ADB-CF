# Township 작업 지침

## 작업 설계와 구현의 기본 원칙

먼저 **다음 행동을 결정하는 데 꼭 필요한 정보가 무엇인지** 따진다. 기존 기능으로 목적을 달성하는 가장 짧고 명확한 흐름을 구성하고, 실제로 확인된 예외에 필요한 처리를 추가한다.

- **판단에 쓰이는 정보만 확인한다.** 정보를 더 읽거나 저장하기 전에 그것이 다음 행동을 바꾸는지 확인한다. 선택 규칙이 이미 정해져 있다면 관련 없는 상품 전체나 수량·가격·남은 시간을 추가로 판독하지 않는다. 주문 부족분 계산처럼 숫자가 판단에 필요한 경우에는 읽는다.
- **현재 화면으로 판단할 수 있으면 별도 관리를 만들지 않는다.** 현재 표시된 이용 가능·휴식 상태로 진행 여부를 정할 수 있다면 이를 위해 타이머, 구매 이력, 복원·정산 절차를 추가하지 않는다.
- **기존 기능을 먼저 재사용한다.** 이미지 등록, 화면 구분, 퍼센티지 좌표, 입력과 결과 확인 기능에 필요한 화면과 행동을 추가한다. 단순한 행동 하나를 위해 별도의 등록 체계나 범용 실행 체계를 만들지 않는다.
- **한 번의 관측을 필요한 판단에 함께 사용한다.** 행동 후 얻은 현재 화면으로 결과 확인과 다음 행동 선택을 함께 처리한다. 이미 확보한 유효한 증거를 같은 목적으로 다시 캡처하거나 판독하지 않는다. 화면이나 판단에 필요한 조건이 달라졌다면 다시 확인한다.
- **확인은 목적에 맞는 가장 단순한 방법을 쓴다.** 고정된 화면 특징은 이미지 인식으로 구분하고, 실제 문구나 숫자 값이 필요할 때 OCR을 사용한다. 대기는 알려진 전환 시간과 결과 확인으로 시작하고, 지연이 확인될 때만 필요한 재관측을 제한적으로 추가한다.
- **예외 처리는 구체적인 근거에 맞춰 추가한다.** 실제 화면, 저장된 증거, 코드에서 확인된 실패 조건을 해결한다. 막연히 가능할 법한 상황을 위해 상태·기록·재시도·검증 단계를 계속 늘리지 않는다. 검증도 변경한 동작과 영향을 받는 기존 동작에 집중한다.
- **단순화하면서 필요한 확인은 유지한다.** 현재 화면과 대상의 식별, 좌표 기준, 행동 결과 확인, 아래의 상품 증거·등록 규약은 지킨다. 불필요한 중복을 줄이되 불확실한 대상을 추측해서 클릭하거나 클릭만으로 성공을 단정하지 않는다.

## 미등록 상품의 관측과 등록

- 상품 인식의 기준 이미지는 실제 게임 화면 캡처에서 얻는다. 캡처 이미지가 없는 상품을 카탈로그 이미지로 대신 인식하지 않는다.
- 미등록 상품을 발견하면 해당 상품의 판단을 보류하고, AI가 원본 게임 화면을 관측해 상품을 확인한다. 저장된 캡처를 먼저 활용하고, 필요하면 현재 화면이나 상품명 상세 화면을 추가로 확인한다.
- 상품을 확실히 확인한 뒤 수량, 가격, 체크 표시, 선택 효과 등 변하는 요소를 제외한 상품 영역을 잘라 등록한다. 원본 캡처와 상품 ID, 원본 식별자와 해시, 잘라낸 위치를 함께 보관한다.
- 같은 상품에 여러 캡처 후보를 등록할 수 있다. 상품 ID는 공유하되 화면 종류와 크기별 적용 범위를 구분한다. 같은 상품의 후보 중 가장 높은 점수를 사용하고, 다른 상품과 구별되는지 확인한다.
- 정상 사례, 다른 상품 사례, 기존 인식 사례로 검증한 뒤 적용한다. 상품의 정체가 불확실하거나 다른 상품과 구별되지 않으면 추측해서 등록하지 않는다.
- 적용 후 현재 화면을 다시 인식해 해당 작업을 재개한다. 이후에는 등록된 이미지로 프로그램이 인식하고, 새로운 예외가 생기면 AI가 다시 관측·등록한다.

### 헬리콥터 납품 중 미인식 증거 수집

헬리콥터 납품 작업 중 실제 주문의 상품 목록을 보고 있을 때만 적용한다. 프로그램이 증거를 수집하고, AI는 저장된 증거를 확인해 앞의 등록·검증 절차를 수행한다. 정보창을 캡처한 것만으로 상품 등록이 완료되거나 배송 가능한 상태가 되는 것은 아니다.

1. **대상 구분** — 상품이 존재하고 슬롯과 상품 이미지의 위치는 확인되지만, 상품의 정체를 인식하지 못한 경우를 수집 대상으로 삼는다. 빈 슬롯, 수량만 읽지 못한 경우, 주문 화면이나 상품 위치 자체를 확인하지 못한 경우는 구분한다. 상품의 정체를 모른다는 이유만으로 확인된 위치에서 정보창을 여는 동작까지 막지 않는다.
2. **클릭 전 증거 확보** — 현재 주문 화면 원본을 보관하고, 해당 슬롯의 상품 이미지를 잘라낸다. 클릭할 위치는 현재 화면에서 확인된 상품 영역 안에서 결정하며 퍼센티지 좌표를 사용한다. 첨부 예시나 과거 캡처의 픽셀 위치를 고정 클릭 위치로 사용하지 않는다.
3. **정보창 열기** — 해당 상품 이미지를 한 번 클릭한다. 같은 상품을 가리키는 이름 정보창이 나타났는지 확인한 뒤 화면을 캡처한다. 상품명, 생산 장소, 생산 시간 등이 표시된 정보창을 수집하며, 정보창의 돋보기나 생산 시설 이동 버튼은 누르지 않는다.
4. **증거 저장** — 정식 루트의 `미인식/헬리콥터/<증거ID>/`에 `item.png`(클릭 전 상품 이미지), `info.png`(이름 정보창이 보이는 전체 화면 캡처), `source.png`(클릭 전 전체 화면), `metadata.json`을 함께 저장한다. 메타데이터에는 슬롯 ID, 원본 화면 식별자·해시, 상품 잘라내기 영역, 클릭 좌표의 기준 영역과 비율, 클릭과 결과 캡처의 연결, 수집 시각과 상태를 기록한다. 상품명은 AI 확인 전까지 미확정으로 둔다. 이 자료는 상품 등록용 증거이며 재고·완료 주문 장부가 아니다.
5. **주문 화면 복귀** — 현재 화면에서 확인된 헬리콥터 제목 영역을 클릭해 정보창을 닫고, 주문 화면으로 돌아왔는지 확인한다. 다음 미인식 품목은 복귀 후 현재 화면에서 위치를 다시 확인한 뒤 같은 절차로 수집한다.
6. **남은 작업 진행** — 증거 수집이 끝나면 미인식 품목이 포함된 주문은 보류하고 다른 처리 가능한 주문과 남은 작업을 진행한다. AI의 상품 등록 완료를 기다리느라 전체 작업을 멈추지 않는다. 등록이 검증·적용되면 해당 주문도 현재 화면을 다시 읽고 처리한다.

- 동일한 화면 종류·크기에서 같은 상품 이미지로 이미 증거 수집을 완료했다면 반복해서 정보창을 열거나 같은 자료를 계속 저장하지 않는다. 상품명이나 슬롯 번호만으로 중복을 판정하지 않으며, 상품 이미지 증거와 적용 범위를 사용한다. 주문이나 이미지가 달라지면 현재 화면을 기준으로 다시 판단한다.
- 정보창이 나타나지 않거나 이름이 가려졌거나 파일 저장에 실패하면 수집 완료로 표시하지 않는다. 확보한 증거와 실패 사유를 남긴다. 주문 화면 복귀가 확인되면 다른 가능한 작업을 진행할 수 있지만, 클릭 결과나 현재 화면이 불확실하면 추가 클릭으로 넘기지 않고 예외로 남긴다.
- 정보창 닫기가 입력 전에 거절되어 실제 클릭이 없었다고 확정된 경우에만, 새 화면의 동일한 정보창과 상품명을 확인해 닫기를 한 번 복구할 수 있다. 복구도 거절되면 반복하지 않는다. 이미 창이 닫혔거나 다른 화면으로 이동했다면 추가 닫기 없이 현재 화면을 다시 관측한다.
- 자동 수집 결과는 AI 확인 대기 자료이다. AI가 이름을 판독할 수 없거나 잘못 연결된 증거를 발견하면 `metadata.json`의 `registrationStatus`를 `unreadable` 또는 `rejected`로 표시한다. 이런 자료는 중복 수집 완료 대상으로 제외하지 않으며, 현재 화면에서 다시 관측한다.
- 구현 시 상품 정체 미인식, 수량 미인식, 위치 미확인을 별도로 표현한다. 상품 정보 열기·닫기와 결과 확인을 독립된 동작으로 연결하고, 여러 미인식 품목의 증거가 서로 섞이지 않도록 품목마다 하나의 증거 묶음을 완성한다.

## 퍼센티지 좌표 규약

- 인식 영역과 클릭·드래그 좌표는 기준 영역에 대한 퍼센티지로 표현한다. 저장값은 `0.0`부터 `1.0`까지의 비율을 사용하며, `0.5`는 50%를 뜻한다.
- 입력 좌표의 기준은 현재 게임 화면 영역이다. 인식 영역은 등록 원본의 기준 영역을 명시한다. 좌표에는 원본 화면, 화면 크기와 기준 영역을 연결한다.
- 실제 픽셀 좌표는 해당 화면을 분석하거나 입력을 실행하는 경계에서 계산한다. 원본 캡처와 이미지 잘라내기의 픽셀 정보는 증거로 보관할 수 있다.
- 화면 크기나 게임 영역이 달라지면 기준을 다시 확인한다. 기준이 없거나 맞지 않는 좌표, 화면 밖 좌표, 과거 화면의 좌표를 현재 입력에 사용하지 않는다. 퍼센티지 정보가 없을 때 픽셀 좌표로 대신 실행하지 않는다.

## 배송 논리

### 헬리콥터 주문 새로고침 대기

- `ORDER ISN'T READY, WAIT OR SPEED IT UP!`와 남은 시간이 표시되는 주문은 새로고침 대기 상태이다. 하단의 초록색 `SPEED UP` 버튼을 배송 버튼으로 판단하거나 누르지 않는다.
- 해당 주문은 건너뛰고 현재 화면에서 확인되는 다른 주문을 선택한다. 주문이 모두 새로고침 대기 상태이면 현재 화면에서 확인된 닫기 버튼으로 마을에 돌아간다. 이후 마을→헬리콥터→마을을 반복하는 것은 핸드폰 화면이 꺼지지 않도록 하기 위한 의도된 동작이다. 주문 화면에 머물러 새로고침을 기다리거나 유료 가속으로 대기를 해소하지 않는다.
- 시장 복귀 후 주문 재확인 중 `SOM_MARKET_RESET_REOBSERVE` 상태가 되는 경우에도 현재 화면에서 확인된 닫기 버튼으로 마을에 돌아간다. 미확인 주문은 처리 완료로 표시하지 않고 남겨 두며, 헬리콥터에 다시 들어가 현재 화면에서 재확인한다. 닫기 버튼 위치가 확인되지 않으면 좌표를 추측하지 않고 다시 관측한다.

### 현재 주문 처리

핵심은 현재 게임 화면을 기준으로 필요한 일을 하고, 과거 장부에 의존하지 않는 것이다. 기차·비행기·헬리콥터 모두 같은 원리를 따른다.

1. **주문 확인** — 현재 요청된 품목과 수량을 읽는다.
2. **필요 물품 정리** — 화면의 보유량을 확인해 부족분을 계산한다. 여러 주문에 쓰이는 재고는 중복 계산하지 않는다.
3. **시장 구매** — 부족한 물품을 필요한 만큼 구매한다.
4. **주문 처리** — 주문 화면에서 충족 여부를 다시 확인하고 배송한다.

필요 물품 목록은 현재 작업을 위한 임시 목록이면 충분하다. 재고 변동이나 완료 주문 이력을 계속 기록·보관할 필요는 없다.

프로그램을 껐다 켰을 때도 이전 주문을 복원하거나 정산하지 않는다. 필요하면 현재 주문과 보유량을 다시 확인해 시작한다. 이미지 등록을 위한 원본 캡처와 상품 증거는 재고·완료 주문 장부와 별도로 보관한다.
